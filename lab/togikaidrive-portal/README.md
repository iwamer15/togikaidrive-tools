# togikaidrive ポータル

設定エディタ(`togikaidrive-config-editor`)・走行データ前処理ツール(`data-preprocessing-tool`)・学習実行ツール(`training-execution-tool`)の3つを、**1つのポート/1プロセス**でタブとして横断的に使えるようにするローカルツール。

## 使い方

```bash
cd ト技会-minicar/lab/togikaidrive-portal
python3 server.py
```

ブラウザで `http://localhost:8898` を開く。上部のタブ(🔧設定エディタ / 🧹前処理 / 🍓ラズパイ実機 / 🖼️アノテーションツール)で切り替えられる(ページ遷移なし)。学習実行(🧠機械学習)と🖼画像学習は、設定エディタの内部タブとして入っている。設定エディタの「🔌 ラズパイ連携」タブは今まで通り設定エディタの内部タブとして使う(ラズパイとの接続設定は3ツール共通で`shared/ssh_connection.json`に保存される)。

## 設計方針(なぜこの形か)

- **3ツールのコード自体はほぼ変更しない**。それぞれ今まで通り単体でも起動できる(`python3 server.py` on 8899/8900/8901)。ポータルはそれに加わる第4の起動方法という位置づけで、既存のワークフローを壊さない。
- 各ツールの`render_page()`(スタンドアロン用フルページ)から、[shared/ui_kit.py](../shared/README.md)の`extract_panel()`で`<div id="toast">`だけを取り除いた「本文」を取り出し、1ページの中にタブパネルとして同居させる。`<header>`はあえて残す(設定エディタの再読み込み/テンプレートボタンなど機能を持つ要素が入っているため)。
- 各パネルのCSSは`scope_css()`でパネルごとにスコープ化する。3ツールとも`:root`/`body`/`html`/`main`を独自に再定義していたため、素朴に連結するとカスケードで衝突する。
- HTTPルーティング(`/save`・`/api/records`・`/train/start`等)は3ツールの間でパス名が重複していないことを確認済みのため、各ツールの`handle_get`/`handle_post`関数(単体サーバーのHandlerクラスからも共有で使う)を順番に試すだけで正しく振り分けられる。
- JS変数名の衝突は1件だけ実在した(前処理ツールと学習実行ツールが両方`const FOLDERS`をトップレベルで定義していた)。学習実行ツール側を`TRAIN_FOLDERS`にリネームして解消済み。
- 3ツールとも同名の`server.py`なので、素朴に`import server`すると`sys.modules["server"]`のキャッシュ衝突が起きる。`importlib.util.spec_from_file_location`で一意な名前で読み込むことで回避している(学習実行ツールが自分の兄弟ツールを読み込む際に使っていた手法と同じ)。

## 既知の制約

- 各ツールがそれぞれ独立に`config_editor`/`data_tool`を読み込む既存の仕組み(モジュール名衝突回避のため)と、ポータル自身の読み込みが独立しているため、起動時に一部のツールのコードが複数回実行される(例: config-editorはポータル用に1回、学習実行ツールの内部importでもう1回)。副作用はいずれもファイル読み書きの再実行程度で実害はないが、起動がわずかに重い。
- 追加のpipライブラリは使わない(標準ライブラリのみ)。
