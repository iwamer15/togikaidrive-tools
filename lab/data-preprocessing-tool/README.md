# 走行データ前処理ツール

`togikaidrive-dev/data/data_<timestamp>/catalog_*.catalog`(DonkeyCar形式のJSON Lines)を、ブラウザでグラフを見ながら安全にトリミングするためのローカルツール。

## 背景

機械学習講座(`2026年_機械学習講座.pdf` P40〜43「データ前処理」)で教えている前処理は、現状**完全に手作業**。

1. SSH越しに`nano`で`catalog_0.catalog`を開く
2. 手動走行開始前/終了後の不要区間、壁への衝突・切り返し等の外乱区間を目視で探す
3. `Ctrl+K`で該当行を1行ずつ削除する

このツールは、同じ作業をブラウザ上のグラフ+範囲指定に置き換える。「教師あり学習には正解データが必要」「Garbage in, garbage out」という前提は変わらないため、**自動的なデータクリーニングは行わず、あくまで人間が判断した範囲を安全に削除するための道具**という位置づけ。

## 使い方

```bash
cd ト技会-minicar/lab/data-preprocessing-tool
python3 server.py
```

ブラウザで `http://localhost:8900` を開く。

## 画面構成

1. **データフォルダ一覧** — `togikaidrive-dev/data/`直下の`data_*`フォルダを新しい順に表示(レコード数・catalogファイル数つき)
2. **グラフ** — 選択したフォルダの全レコード(複数catalogファイルにまたがっていても通し番号で結合)を、
   - ステアリング/スロットルの折れ線グラフ
   - 超音波センサー5点の距離の折れ線グラフ(2000mm=未検知)
   の2つで可視化する。手動走行開始前(値が動かない区間)や外乱(急な値の変化)を視覚的に見つけやすい
3. **トリミング** — 「先頭を削除」「末尾を削除」(講座で教えている操作そのもの)に加え、途中の任意範囲を指定して削除できる。複数の削除範囲を追加でき、グラフ上にオレンジの帯としてプレビュー表示される
4. **保存** — 「現在N件 → 削除後M件」のプレビューを確認してから書き換えを実行する

## 安全性

- **標準ライブラリのみ**で動作(pip install不要)
- 保存のたびに、実際に変化するcatalogファイルだけ`catalog_N.catalog.bak.<日時>`の自動バックアップを作成してから書き換える(触っていないcatalogファイルはバイト単位で無変化)
- `manifest.json`・`images/`ディレクトリには一切手を触れない
- 万が一おかしくなったら、直前のバックアップファイルを元のファイル名にコピーし直せば元に戻る

```bash
# 元に戻す例
cp catalog_0.catalog.bak.20260908_015200 catalog_0.catalog
```

## 設計上の重要な注意(なぜmanifest.jsonの`deleted_indexes`を使わないか)

DonkeyCar形式の`manifest.json`には、削除済み行のインデックスを記録する`deleted_indexes`という仕組みがある。しかし`train_pytorch.py`の`load_donkeycar_data()`を読むと、この判定は**catalogファイルごとに0から数え直した位置**に対して行われており([train_pytorch.py:169-179](../../togikaidrive-dev/train_pytorch.py))、複数のcatalogファイルにまたがるデータでは「削除したい行と同じ相対位置の、他のcatalogファイルの行」まで意図せず削除扱いになってしまう。1ファイル最大1000レコードで自動分割される実際の収集データでは複数ファイルに分かれるケースが多いため、この仕組みは使わず、**対象のcatalogファイルを直接安全に書き換える**方式にしている(講座で教えている手動編集と同じ結果になる、より確実な方法)。`train_pytorch.py`自体は変更しない。

## 制約

- 対象は測距センサー(nn)データを想定している。画像ベース(donkeycar/resnet18等)のカタログも閲覧はできるが、画像プレビュー機能はまだ無い(必要に応じて拡張予定)
- 正規化やモデル学習には一切関与しない(「悪いデータ行を除く」ことだけを担当する)
