# 学習実行パネル

`togikaidrive-dev/train_pytorch.py`(対話式の機械学習実行スクリプト)を、ブラウザから起動・進捗監視するためのローカルツール。

## 背景

`train_pytorch.py`にはCLI引数や環境変数での非対話実行オプションが無く、`python train_pytorch.py`を実行すると「データフォルダ選択→学習モデル選択→エポック数入力→開始確認」と対話式(`input()`)にプロンプトが進む設計になっている。

このツールは`train_pytorch.py`自体を一切変更せず、サブプロセスとして起動して標準入力に決まった順で回答を流し込み(実際に人が打つのと同じ操作を自動化するだけ)、標準出力をポーリングでブラウザにリアルタイム表示する。

## 使い方

```bash
cd ト技会-minicar/lab/training-execution-tool
python3 server.py
```

ブラウザで `http://localhost:8901` を開く。

学習には`Adafruit_PCA9685`と同様、`torch`等のライブラリが必要。ラズパイ上で実機学習を回す場合は、`togikaidrive-dev/venv`のPythonが自動的に使われる(存在すればそちらを優先、無ければシステムのpython3にフォールバックしてエラーをそのままログに表示する)。

```bash
# 実機で直接起動する場合の対象パス(自動判定されるので手動指定は不要)
togikaidrive-dev/venv/bin/python3
```

## 画面構成

1. **現在のconfig.py設定** — `EPOCHS`/`BATCH_SIZE`/`HIDDEN_DIM`/`NUM_HIDDEN_LAYERS`/`MODEL_DIR`を読み取り専用で表示。変更したい場合はtogikaidrive-config-editorで行う(このツールはconfig.pyに一切書き込まない)
2. **学習の実行** — データフォルダ選択(`data-preprocessing-tool`と同じフォルダ一覧を再利用)・エポック数(空欄でconfig.pyのデフォルト)・継続学習するかのチェックボックスを指定して「学習を開始」
3. **実行状況** — 状態バッジ(待機中/実行中/完了/失敗/停止)と、標準出力をそのまま流し込むログ表示。1.5秒間隔でポーリングして追記する

## v1のスコープ: 測距データ(nn)のみ

実際に収集済みのデータはすべて測距センサーのみ(画像なし)のため、学習プランは`nn`に固定している。画像ベース(donkeycar/resnet18等)は、学習完了後のモデル変換確認プロンプト(Jetson/RPi実行時のみ発生)など条件分岐が増えて標準入力の自動応答が複雑になるため、カメラ画像データの収集が実際に始まってから対応する(削除ではなく将来の拡張候補)。

## 標準入力の自動応答について

`train_pytorch.py`を実際に読み、`main()`実行時に発生しうる`input()`呼び出しを全数調査した上で、以下の順で回答を送っている。

| 順番 | プロンプト | 条件 |
|---|---|---|
| 1 | データフォルダ選択 | `data/`配下のフォルダが2個以上のときだけ発生。1個ならスキップ |
| 2 | 学習モデル選択 | 常に発生(v1では常に`1`=nnを送る) |
| 3 | エポック数入力 | 常に発生 |
| 4 | この設定で学習を開始しますか(Y/n) | 常に発生。常に`Y`を送る |
| 5 | 既存モデルからの継続学習確認(Y/n) | 対応する接頭辞(`nn_`等)の`.pth`が`models/`に既にある場合のみ発生 |

5番目は「既存モデルの有無」を正確に予測するのが難しい(プレフィックス対応表の複製が必要でズレるリスクがある)ため、**発生するかどうかに関わらず常に回答を送っている**。nnプランではこれより後に`input()`は無いことをコードで確認済みなので、不要な場合に送った回答は単に読み捨てられるだけで安全。

データフォルダの番号は、このツール(および`data-preprocessing-tool`)では見やすさのため新しい順で一覧表示しているが、`train_pytorch.py`の`get_data_directory()`は`data_folders.sort()`で**古い順**に並べ替えてから番号を振る。このツールは選択されたフォルダ名から、`train_pytorch.py`が実際に振る番号を`sorted()`で計算し直してから送るので、表示順の違いによる選択ミスは起きない。

## 安全設計

- `config.py`には一切書き込まない(エポック数等の指定はそのプロセスの標準入力経由のみで完結し、`train_pytorch.py`自身も`config.EPOCHS = epochs`のようにメモリ上でしか変更しないため、元のスクリプトの挙動と完全に一致する)
- 同時に2つの学習は実行できない(実行中に`学習を開始`しようとするとエラーになる)
- 「停止」は`SIGTERM`で終了を試みる。学習ループの途中では即座に止まらない場合がある

## 制約

- `torch`等が無い環境(開発機など)では起動直後に`ModuleNotFoundError`でプロセスが失敗するが、それがそのままログに表示されるだけでツール自体はクラッシュしない
- 実際の学習の動作確認(進捗表示・モデル保存・エポック増加時の所要時間など)は、`torch`が使える環境(ラズパイの`togikaidrive-dev/venv`等)で行う必要がある
